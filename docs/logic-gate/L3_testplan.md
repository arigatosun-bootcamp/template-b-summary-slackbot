# L3 テスト計画（LLM原則禁止）

「ちゃんと動く」を確認するためのテスト項目を書く。
3種類をバランスよく混ぜるのがコツ。

- **正常**：普通に使ったときに期待通り動くか
- **異常**：おかしな入力や操作をしたときにちゃんとエラーになるか
- **境界**：ギリギリの値（0件、上限ちょうど、空文字など）で壊れないか

### 履歴まわり

| ID | 種別 | 何をする？（操作や入力） | どうなれば正解？ | なぜこのテストが要る？ |
|---|---|---|---|---|
| T1 | 正常 | 複数回記事要約した後にチャットで履歴を表示してとコメントする | 過去の要約タイトルが新しい順に一覧表示される | 履歴がちゃんと保存されて表示されるか確認するため |
| T2 | 正常 | 履歴一覧からもう一度読みたいタイトルを伝える | 過去に表示した内容で要約が再度自動で投稿される | 詳細が正しく見られるか確認するため |
| T3| 境界 | 1回も記事要約していない状態で履歴を表示してとコメントする | 「まだ要約履歴がありません」とコメントが返ってくる（エラーにはならない） | 0件のときに壊れないか確認するため |

| ID | 種別 | 何をする？（操作や入力） | どうなれば正解？ | なぜこのテストが要る？ |
|---|---|---|---|---|
| T4| 正常 | 気になったURLを貼り付ける | URLの中の内容がわかりやすく要約される |一番基本的な操作が動くことを確認するため  |
| T5| 異常 | 存在しないURLを貼り付ける | このURLは存在しませんと表示される | URLの打ち間違いやコピー貼り付けミスに気づいてもらうため |

### 書き方のヒント
- 他の人がこの表だけ見て、同じ操作を再現できるくらい具体的に書く
- 「正しく動く」ではなく「〇〇が表示される」「△△のエラーメッセージが出る」のように書く
