# L1 要件分解（LLM原則禁止）

## 1. 目的（誰の・何の困りごとを解決する？）
- 背景（なぜ作る？）：
誰が困っている？：長い文章を読むのが苦手なビジネスパーソン
何に困っている？：長い文章を読むのが苦手で気になる記事タイトルを見ても読むまで至れない
どう解決する？：気になった記事のURLを貼ることでAIが分かりやすい短い文章で要約を生成してくれるアプリ（Slack Bot）を作る

- 解決したい困りごと：
- 「できたらOK」と言える状態：Slackで完結するかたちで気になった記事のURLを貼ることでAIが分かりやすい文章を作成し要約結果をSlackチャンネルに自動投稿される。また要約の過去の履歴も見れる状態

## 2. やること / やらないこと
### 今回やること


-過去の要約履歴を一覧で確認できる
-AIでネット記事をわかりやすく要約できる
-要約した記事を自動でSlackチャンネルに投稿される

### 今回やらないこと（次回以降 or 対象外）
-マイページ（プロフィール編集） → 最低限の設定画面のみ作る
-過去の要約からおすすめの機能を自動投稿（あくまで自分が気になったものを要約する）

## 3. 使い方の流れ（ユーザー目線で）
ユーザーが何をして → アプリが何をして → どんな結果が返るか、を書く。

- 流れ1：要約を依頼　　気にる記事を見つける → そのURLをSlackのチャンネルに記入 → AIが要約を作成 → 要約結果をSlackチャンネルに自動投稿
- 流れ2：要約履歴確認　　Slackチャンネルに履歴を表示してと伝える → スラックボットが履歴のタイトルを表示してくれる → 確認したい内容をコメントする→スラックボットがその時の要約を再度自動投稿してくれる

## 4. 保存が必要なデータ
どんな情報をデータベースに保存する必要があるか、ざっくり洗い出す。
要約履歴：後からでも要約の履歴が確認できるようにするため
Slackのチャンネル：AIが記事要約後にどこに表示するか忘れないようにするため

## 5. 完了条件（「これができたらOK」を具体的に）
曖昧な表現ではなく、実際に画面やログで確認できる形で書く。

- 条件1：（要約）
　- URLをチャンネルに送るとチャットボットが自動で要約を開始しSlackチャンネルに要約が自動投稿される
　-貼り付けたURLの要約が生成される（関係のないサイトではない）
　-URLを送る際に簡単　普通　詳しく　の三段階から要約のレベルを調節できる
　-URLだけを送った時は三段階の真ん中の普通の要約で返答が返ってくる
　- どうやって確認する？：実際にURLを送ってSlackチャンネルに要約が投稿されているか目視で確認する。また実際にURL内の記事を自分で確認し要約の内容とあっているかを目視で確認する。
　　URLを送るのを何回か繰り返してスムーズに要約が生成されるか確認する
