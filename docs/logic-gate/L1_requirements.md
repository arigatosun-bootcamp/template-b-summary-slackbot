# L1 要件分解（LLM原則禁止）

## 1. 目的（誰の・何の困りごとを解決する？）
- 背景（なぜ作る？）：
誰が困っている？：長い文章を読むのが苦手なビジネスパーソン
何に困っている？：長い文章を読むのが苦手で気になる記事タイトルを見ても読むまで至れない
どう解決する？：気になった記事のURLを貼ることでAIが分かりやすい短い文章で要約を生成してくれるアプリを作る

- 解決したい困りごと：
- 「できたらOK」と言える状態：ユーザーがログインし気になった記事のURLを貼ることでAIが分かりやすい文章を作成し要約結果をSlackチャンネルに自動投稿される。また要約の過去の履歴も見れる状態

## 2. やること / やらないこと
### 今回やること
-ユーザー認証（メール＆パスワードでの登録・ログイン・パスワードリセット）
-アカウント削除機能
-過去の要約履歴を一覧で確認できる
-AIでネット記事をわかりやすく要約できる
-要約した記事を自動でSlackチャンネルに投稿される

### 今回やらないこと（次回以降 or 対象外）
-マイページ（プロフィール編集） → 最低限の設定画面のみ作る
-過去の要約からおすすめの機能を自動投稿（あくまで自分が気になったものを要約する）

## 3. 使い方の流れ（ユーザー目線で）
ユーザーが何をして → アプリが何をして → どんな結果が返るか、を書く。

- 流れ1：初回利用　　ユーザーがアプリのURLにアクセスする → ログイン画面が表示される → 「新規登録」を押してメールとパスワードを入力する → 確認メールが届く → メール内のリンクをクリックする → ログイン画面に戻りメールとパスワードでログインする → トップ画面が表示される
- 流れ2：要約を依頼　　気にる記事を見つける → そのURLをアプリ画面に記入 → AIが要約を作成 → 要約結果をSlackチャンネルに自動投稿
- 流れ3：要約履歴確認　　アプリにログインする → TOP画面から要約の履歴ページを確認する → 確認が終わったらTOPへ戻るボタンでTOPに戻る

## 4. 保存が必要なデータ
どんな情報をデータベースに保存する必要があるか、ざっくり洗い出す。
ユーザー情報（メールアドレス）: ログイン認証に必要。次回ログイン時にデータを紐づけるため
要約履歴：後からでも要約の履歴が確認できるようにするため
Slackのチャンネル：AIが記事要約後にどこに表示するか忘れないようにするため

## 5. 完了条件（「これができたらOK」を具体的に）
曖昧な表現ではなく、実際に画面やログで確認できる形で書く。

- 条件1（認証）:
  - メールとパスワード（8文字以上）で新規登録ができる
  - 確認メールが届き、リンクをクリックすると認証が完了する
  - ログイン後にトップ画面が表示される
  - どうやって確認する？：実際にメールアドレスで登録し、確認メールのリンクを踏み、ログインしてトップ画面が出ることを目視で確認する

- 条件2：（要約）
　- URLを貼り付けて要約するボタンを押すと要約がSlackチャンネルに自動投稿される
　-貼り付けたURLの要約が生成される（関係のないサイトではない）
　-要約生成中はオーディングが表示される（10秒以内に生成完了する）
　- どうやって確認する？：実際にURLを貼り付けてSlackチャンネルに要約が投稿されているか目視で確認する。また実際にURL内の記事を自分で確認し要約の内容とあっているかを目視で確認する。
　　生成を何回か繰り返してスムーズに生成されるか確認する
