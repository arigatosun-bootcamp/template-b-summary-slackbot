# L2 品質チェックリスト（LLM原則禁止）

コードを書く前に「これだけは絶対に守る」ルールを決めておく。
バグを出してから直すより、先に「壊れたらどうなるか」を考えておく方がずっと楽。

| 守るべきルール（例：空欄で送信できない） | なぜ必要？ | どうやって気づく？（例：テスト、目視） | 破れたらどうする？（例：エラー表示、ログ出力） |
|---|---|---|---|

| 生成内容はSlackチャンネルに自動投稿される | スラックに投稿されなければ生成できたことにならず履歴としても確認できないから | 目視（生成後にSlackチャンネルに表示されているか確認） | Slackにうまく生成できませんでした　再度生成を行いますのテキストがチャットに表示される |
|URLが含まれていないメッセージでは要約されない|URLがないと記事が確認できないから|目視（テキストのみで送る）|URLを追加してくださいとメッセージを送る|
|存在しないページにはメッセージで内容がないことを伝える|ユーザーは存在しないページと気づいていない|テスト（存在しないページを送る）|このページは存在しませんとメッセージで送る|
|要約時間は30秒以内にする|ユーザーがそれ以上は待てない|テスト（実際にURLを送ってどれぐらいで生成されるか確認する）|時間がかかりそうな場合はメッセージで生成に時間がかかっていることをメッセージで送る|
|AIが動かなくなったら壊れている内容をメッセージで伝える|URLを送って返答がないと困るから|テスト（URLを送って実際に動くか確認する|エラーで要約できないメッセージを送る（その時点でエラー内容がわかればその内容も伝える|
|要約レベルは間違わないように生成される|ユーザーが求めている読みやすさがあるから|目視（指定の文量になっているか確認する）|再度生成するのでお待ちくださいと再生成を始める|

### 書き方のヒント
- 「〜できない」「〜してはいけない」のような **NG条件** で考えると書きやすい
- 例：「未ログインユーザーがデータを見られてはいけない」→ 認証チェックが必要
