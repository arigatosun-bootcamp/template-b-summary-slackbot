# 機能要件書 — Summary Slackbot

## F-01: 新規登録

| 項目 | 内容 |
|------|------|
| 概要 | メールアドレスとパスワードで新規ユーザー登録 |
| 画面 | 新規登録画面 |
| 認証基盤 | Supabase Auth |

### 入力

| フィールド | 型 | 必須 | バリデーション |
|-----------|-----|------|--------------|
| メールアドレス | string | 必須 | メール形式チェック |
| パスワード | string | 必須 | 8文字以上 |

### 処理フロー
1. バリデーションチェック
2. Supabase Auth の `signUp()` を呼び出し
3. 確認メールが自動送信される
4. ユーザーがメール内リンクをクリックして認証完了

### エラー処理

| エラー | メッセージ |
|--------|----------|
| メール空欄 | 「メールアドレスを入力してください」 |
| パスワード7文字以下 | 「パスワードは8文字以上で入力してください」 |
| 登録済みメール | 「このメールアドレスは既に登録されています」 |

## F-02: ログイン

| 項目 | 内容 |
|------|------|
| 概要 | メールとパスワードでログインし、トップ画面に遷移 |
| 画面 | ログイン画面 |

### 入力

| フィールド | 型 | 必須 |
|-----------|-----|------|
| メールアドレス | string | 必須 |
| パスワード | string | 必須 |

### 処理フロー
1. Supabase Auth の `signInWithPassword()` を呼び出し
2. 成功 → トップ画面（要約入力画面）に遷移
3. セッション情報をブラウザに保存

### エラー処理

| エラー | メッセージ |
|--------|----------|
| メールまたはパスワードが違う | 「メールアドレスまたはパスワードが正しくありません」 |
| メール未認証 | 「メールアドレスの認証が完了していません」 |

---

## F-03: パスワードリセット

| 項目 | 内容 |
|------|------|
| 概要 | パスワードを忘れた場合にリセットメールを送信 |
| 画面 | ログイン画面 → パスワードリセット画面 |

### 処理フロー
1. 「パスワードを忘れた方はこちら」リンクをクリック
2. メールアドレスを入力して送信
3. Supabase Auth の `resetPasswordForEmail()` を呼び出し
4. リセットメールが届く → 新しいパスワードを設定

---

## F-04: ログアウト

| 項目 | 内容 |
|------|------|
| 概要 | セッションを終了してログイン画面に戻る |

### 処理フロー
1. ヘッダーの「ログアウト」ボタンをクリック
2. Supabase Auth の `signOut()` を呼び出し
3. ログイン画面にリダイレクト

---

## F-05: アカウント削除

| 項目 | 内容 |
|------|------|
| 概要 | アカウントと関連データを完全に削除 |
| 画面 | 設定画面 |

### 処理フロー
1. 「アカウント削除」ボタンをクリック
2. 確認ダイアログ「本当に削除しますか？この操作は取り消せません」を表示
3. 「削除する」→ ユーザーデータと要約履歴を削除 → ログイン画面に遷移
4. 「キャンセル」→ 何も起きず設定画面のまま

## F-06: 記事要約

| 項目 | 内容 |
|------|------|
| 概要 | URLを入力してAIが要約を生成し、結果を画面に表示＋Slackに投稿 |
| 画面 | トップ画面（要約入力画面） |

### 入力

| フィールド | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| URL | string | 必須 | 要約したい記事のURL |
| 要約レベル | select | 任意 | 簡単 / 普通（デフォルト） / 詳しく |

### 要約レベル

| レベル | 出力量 | プロンプト指示 |
|--------|--------|--------------|
| 簡単 | 3行程度 | 最も重要なポイントを3行で要約 |
| 普通 | 5〜8行 | 主要なポイントを箇条書きで要約 |
| 詳しく | 15行程度 | 詳細な内容を網羅的に要約 |

### 処理フロー
1. URLと要約レベルを入力して「要約する」ボタンをクリック
2. ローディング表示「記事の要約を生成しています...」
3. Python API に POST リクエスト送信
4. API内部処理:
   - 重複URLチェック → 過去に要約済みなら確認ダイアログ表示
   - URLをスクレイピング（requests + BeautifulSoup）
   - LLMで要約生成（Claude or ChatGPT）
   - 要約をSupabaseに保存
   - Slack Incoming Webhookで要約をSlackチャンネルに投稿
5. 画面に要約結果を表示

### 要約結果の表示フォーマット

```
📝 [記事タイトル]

・要約ポイント1
・要約ポイント2
・要約ポイント3
...

🔗 元記事: https://example.com/article
```

### Slack投稿フォーマット

```
📝 *記事タイトル*

・要約ポイント1
・要約ポイント2
・要約ポイント3

🔗 元記事: https://example.com/article
📊 要約レベル: 普通
👤 要約者: user@example.com
```

### エラー処理

| エラー | メッセージ |
|--------|----------|
| URL空欄 | 「URLを入力してください」 |
| 無効なURL形式 | 「正しいURLを入力してください」 |
| ページが存在しない（404等） | 「このページは存在しません」 |
| スクレイピング失敗 | 「この記事の内容を取得できませんでした」 |
| LLM APIエラー | 「要約の生成に失敗しました。もう一度お試しください」 |
| Slack投稿失敗 | 「Slackへの投稿に失敗しました（要約は保存済み）」 |
| タイムアウト（10秒超過） | 「要約の生成がタイムアウトしました。もう一度お試しください」 |

## F-07: 重複URLチェック

| 項目 | 内容 |
|------|------|
| 概要 | 過去に要約したURLと同じ場合、再要約するか確認 |

### 処理フロー
1. URL入力時にSupabaseで過去の要約を検索
2. 要約済みの場合、確認ダイアログを表示
   - 「この記事は以前に要約しています。再要約しますか？」
   - 「再要約する」→ 新しい要約を生成
   - 「過去の要約を見る」→ 履歴詳細画面に遷移
   - 「キャンセル」→ 入力画面に戻る

---

## F-08: 要約履歴一覧

| 項目 | 内容 |
|------|------|
| 概要 | 過去の要約を新しい順に一覧表示 |
| 画面 | 履歴一覧画面 |

### 表示項目

| 項目 | 説明 |
|------|------|
| 記事タイトル | スクレイピングで取得したタイトル |
| 元URL | 要約した記事のURL |
| 要約レベル | 簡単 / 普通 / 詳しく |
| 生成日時 | 要約した日時 |

### 処理
- ログインユーザーの要約のみ表示（他ユーザーの履歴は見えない）
- 新しい順にソート
- 履歴0件の場合「まだ要約履歴がありません」と表示

| 項目 | 内容 |

## F-11: LLM切り替え

| 項目 | 内容 |
|------|------|
| 概要 | 環境変数でClaude / ChatGPTを切り替え |

### 設定

| 環境変数 | 値 | 使用API |
|---------|-----|---------|
| `LLM_PROVIDER=anthropic` | Claude | Anthropic API |
| `LLM_PROVIDER=openai` | ChatGPT | OpenAI API |

- 切り替えはサーバー側の環境変数で行う（ユーザー画面からは切り替えない）
- どちらのLLMで要約したかを履歴に記録する
