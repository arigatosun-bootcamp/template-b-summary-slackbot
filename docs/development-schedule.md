# 開発スケジュール — Summary Slackbot

## 概要

- 作業日数: **5日間（Day1〜Day5）**
- 1Dayあたりの作業時間: **2〜3時間**
- 合計: **10〜15時間**

---

## Day1: 環境構築 + Slack Bot基本動作

**ゴール: Slackでメンションしたら「Hello!」と返ってくる状態**

| タスク | 内容 | 成果物 |
|--------|------|--------|
| Slack App作成 | Slack APIでApp作成、Bot Token・Signing Secret取得 | Slack App設定完了 |
| 環境変数設定 | `.env.local` にトークン類を設定 | .env.local |
| Pythonプロジェクト準備 | requirements.txt作成、依存ライブラリインストール | requirements.txt |
| イベントハンドラ作成 | `api/slack/events.py` でメンション受信 → 固定テキスト返信 | api/slack/events.py |
| ヘルスチェック作成 | `api/health.py` | api/health.py |
| 設定管理作成 | `api/config.py` で環境変数読み込み | api/config.py |
| ローカル動作確認 | ngrok等でSlackイベントを受信できるか確認 | 動作確認済み |

**確認ポイント:**
- [ ] `@bot テスト` とメンションして「Hello!」が返ってくる
- [ ] ヘルスチェック `GET /api/health` が `{ "status": "ok" }` を返す

---

## Day2: スクレイピング + メッセージ解析

**ゴール: URLを送ったら記事タイトルと本文が取得できる状態**

| タスク | 内容 | 成果物 |
|--------|------|--------|
| メッセージ解析 | `api/message_parser.py` でURL抽出・レベル判定・コマンド判定 | api/message_parser.py |
| スクレイピング | `api/scrape.py` でURL→タイトル+本文を取得 | api/scrape.py |
| イベントハンドラ更新 | URL検出→スクレイピング→結果をスレッド返信 | api/slack/events.py（更新） |
| Slack送信モジュール | `api/slack_client.py` でスレッド返信・処理中メッセージ | api/slack_client.py |
| Bot自己防御 | Bot自身の投稿を無視するフィルタを実装 | api/slack/events.py（更新） |

**確認ポイント:**
- [ ] `@bot https://example.com` で記事タイトルと本文がスレッドに返ってくる
- [ ] 「要約を生成中です...」メッセージが先に表示される
- [ ] URLなしメッセージに「URLを追加してください」と返る
- [ ] Bot自身の投稿に反応しない

## Day3: LLM要約 + 要約レベル対応

**ゴール: URLを送ったらAIが要約してスレッドに返す状態**

| タスク | 内容 | 成果物 |
|--------|------|--------|
| LLM要約モジュール | `api/summarize.py` でClaude/ChatGPT両対応 | api/summarize.py |
| プロンプト実装 | 要約レベル別のプロンプトを構築 | api/summarize.py（内部） |
| 要約フォーマット | 📝タイトル+箇条書き+元記事URLのフォーマットで返信 | api/slack_client.py（更新） |
| エラーハンドリング | 存在しないURL・APIエラー・タイムアウト時のエラーメッセージ | 各モジュール |
| LLM切り替え | 環境変数 `LLM_PROVIDER` でClaude/ChatGPTを切り替え | api/config.py（更新） |

**確認ポイント:**
- [ ] `@bot URL` で普通の要約（5〜8行）が返る
- [ ] `@bot URL 簡単` で短い要約（3行）が返る
- [ ] `@bot URL 詳しく` で詳細な要約（15行）が返る
- [ ] 存在しないURLで「このページは存在しません」と返る
- [ ] LLM_PROVIDERを変えて両方のAPIで要約できる

## Day4: DB連携（履歴保存・表示・重複チェック）

**ゴール: 要約が保存され、履歴表示と重複チェックが動く状態**

| タスク | 内容 | 成果物 |
|--------|------|--------|
| Supabase設定 | Supabaseプロジェクト作成、create_tables.sql実行 | Supabaseテーブル作成完了 |

**確認ポイント:**
- [ ] 要約後にSupabaseのsummariesテーブルにデータが保存される
- [ ] `@bot 履歴` で過去の要約が一覧表示される

- [ ] 同じURLを送ると「再要約しますか？」と聞かれる

## 全体タイムライン

```
Day1  環境構築 + Bot基本動作      → 🤖「Hello!」が返る
Day2  スクレイピング + 解析        → 📄 記事タイトルが返る
Day3  LLM要約 + レベル対応        → 📝 AI要約が返る ← ここが核心
Day4  DB連携 + 履歴機能           → 💾 履歴が使える
Day5  デプロイ + テスト + 仕上げ   → 🚀 本番稼働
```

---

## リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| Slack APIの設定でつまずく | Day1が遅れる | 公式ドキュメントを参照、ngrokで動作確認 |
| スクレイピングがうまくいかないサイトがある | 一部URLで要約できない | エラーハンドリングで対応、対応URLを限定 |
| LLM APIの応答が遅い | ユーザー体験が悪い | 処理中メッセージ+30秒タイムアウト |
| Vercelのサーバーレス制約 | デプロイ時にエラー | ローカルで十分テストしてからデプロイ |
| Day3以降のタスクが溢れる | スケジュール遅延 | Day3のLLM要約を最優先、履歴機能は最小限でリリース |
